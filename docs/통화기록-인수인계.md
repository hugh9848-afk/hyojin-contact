## 0. 한 줄

학원폰으로 오가는 전화를 **손대지 않고** 글로 남겨, 학생·반별로 찾아볼 수 있게 만드는 일.
1차로 수동 입력 화면을 만들었고, 사용자가 "손 많이 가서 안 쓰게 될 것"이라 해
**맥미니 자동 전사 파이프라인**으로 방향을 바꿔 구현·푸시한 상태.

## 2. 확인된 기술적 사실 (재검토해도 바뀌지 않는 것)

1. **웹앱은 폰의 통화목록(CallLog)을 읽을 수 없다.** iOS·안드로이드 모두 브라우저에 권한을 주지 않음.
2. **삼성 '텍스트 변환 어시스트'가 만든 전사본을 서드파티가 읽는 공식 경로는 없다.**
   전화앱 내부 저장소에 있고 공개 API가 없음. 화면의 '공유' 버튼으로 내보내는 것은 건당 수동.
3. 따라서 자동화하려면 **녹음 파일(.m4a)을 우리가 직접 받아 우리 손으로 전사**해야 한다.
   → 현재 설계의 출발점.
4. 안드로이드 네이티브 앱이면 `READ_CALL_LOG` 로 누구와·언제·몇 분은 자동 수집 가능.
   (전사는 별개 문제 — 여전히 직접 해야 함)

## 4. 현재 구조

```
학원폰(S22)            구글드라이브           맥미니(24h)                    폰·PC
전화 자동 녹음   →    _자동화/통화녹음   →   callnotes.py --watch      →   calls.html
(삼성 기본 기능)      (Autosync 앱)          ffmpeg → whisper.cpp           ('자동' 배지)
                                             → 요약·학생매칭·후속조치
                                             → POST 중계기(앱스스크립트)
```

전사는 맥미니 로컬 whisper → **비용 0원, 음성이 외부로 나가지 않음.**

### 기록 한 건의 모양 (맥미니 ↔ 중계기 ↔ 화면 공통)

```json
{
  "id": "auto-통화-녹음-김지우-어머님-260917-182233",
  "source": "auto",           // auto = 맥미니가 만든 것, 없으면 손으로 적은 것
  "name": "김지우", "role": "학부모", "cls": "경기1일",
  "phone": "010-1234-5678",
  "at": "2026-09-17T18:22",   // 로컬 시각, 초 없음
  "dir": "",                  // in | out | ""(모름 — 파일이름으로는 알 수 없음)
  "tag": "결석",               // 상담·결석·수납·보강·문의·기타
  "memo": "· 핵심 문장\n· ...", // 자동 요약 (사용자가 고칠 수 있음)
  "text": "통화 전문",
  "star": false,
  "todo": {"on": true, "text": "일정 확인해서 연락", "due": "", "done": false},
  "edited": false,            // true면 맥미니가 덮어쓰지 않음 (전문만 갱신)
  "file": "원본 녹음 파일 이름"
}
```

### 중계기 인터페이스

- `GET  ?v=<토큰>&api=calls&limit=500&callback=<jsonp>` → `{ok, stamp, count, records[]}`
- `POST {token, records[]}` → `{ok, added, total}` — id 기준 갱신, 시각순 정렬, 최근 2000건 보관
- JSONP를 쓰는 이유: **기존 `roster.html`이 쓰는 검증된 방식과 동일**하게 맞춤 (CORS 회피)

### 자동 판정 규칙 (모두 규칙 기반 — LLM 아님)

- **파일명 파싱**: `통화 녹음 <상대>_YYMMDD_HHMMSS.m4a` 등 3가지 날짜 꼴
- **학생 매칭**: `classes.json`(공개) → 상대 표시에서 먼저, 없으면 전문 앞 1500자에서
- **요약**: 낱말 가중치(결석4·보강4·수강료4·취소4…) + 날짜 표현 +3, 상위 5문장을 원래 순서로
- **유형**: 낱말 빈도로 6종 중 택1
- **후속조치**: `(연락|보내|알려|확인…) + (드리|드릴|겠습…)` 패턴의 **마지막** 문장

## 5. 검증한 것 / 검증하지 못한 것 ★

재기획 시 가장 중요한 칸입니다.

### 실제로 돌려서 확인함
- `callnotes.py` 순수 로직 **28개 시험 통과** (파일명 파싱·전화번호·학생매칭·요약·유형·후속조치·명단읽기)
- 가짜 녹음 2건으로 **end-to-end 드라이런**: 폴더 감시 → 기록 생성 → 중복 처리 방지 → JSON 저장
- 가짜 중계기 + Playwright로 **화면 동기화**: 자동 기록 수신, '자동' 배지, 마지막 동기화 표시
- **손댄 기록 보호**: 사용자가 고친 기록에 맥미니 것이 와도 덮어쓰지 않고 전문만 갱신 ✔
- **삭제 유지**: 지운 자동 기록이 재동기화로 되살아나지 않음(묘비 방식) ✔
- 틀린 토큰 차단, 토큰+공유텍스트 동시 수신, 수동 입력·공유 수신·검색·전문 펼침 ✔

### 확인하지 못함 (이 환경에 맥도 폰도 없음)
- **whisper 전사 자체** — 한국어 통화 품질, 속도, 맥미니 실제 사양에서의 부하
- **삼성 자동 녹음 기능의 존재 여부와 실제 파일명 형식** ← 전체 설계의 전제
- **Autosync가 `/Call` 폴더를 읽을 수 있는지** (Android 스코프드 스토리지 이슈 가능)
- 앱스스크립트 중계기의 실제 배포·동작
- 구글드라이브 데스크톱 앱이 해당 폴더를 맥미니로 내려받는지
